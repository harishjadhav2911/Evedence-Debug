EvidenceDebug AI — Architecture & Methodology

Retrieval-Augmented Generation for Grounded Code Explanations

1. The Problem with Ungrounded Code Assistants

Generic large language models frequently hallucinate non-existent API parameters, misinterpret subtle runtime semantics, and suggest speculative fixes without verifiable justification. In mission-critical software, a developer cannot trust an AI suggestion without proof.

2. Our Philosophy: Retrieval First, Generation Second

EvidenceDebug AI enforces a strict protocol: before a single explanatory word is synthesized, the system must parse AST signals from the code, query the indexed knowledge base of official specifications and standards, and retrieve exact passages. Every claim in the final explanation is tagged with its evidence category:

DOC-BACKED Directly supported by a retrieved documentation passage from the verified corpus.
GENERAL KNOWLEDGE Common programming language syntax or standard algorithmic principles.
UNSUPPORTED Speculative inference or heuristic advice requiring independent developer verification.

3. Upcoming Django Backend Integration Points

This frontend interface is architected to seamlessly attach to the upcoming Django RAG backend:

  • POST /api/v1/analyze/ — Accepts source code, language, and problem context; runs AST parser and returns trace ID.
  • GET /api/v1/retrieval-trace/{id}/ — Streams retrieved passages, chunk scores, and source metadata via SSE.
  • POST /api/v1/documents/upload/ — Multipart upload for PDF/TXT document chunking and vector embedding generation.
  • POST /api/v1/grounding/verify/ — Runs NLI (Natural Language Inference) claim-evidence alignment checks.
